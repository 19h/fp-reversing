# Live CoreADI peer entitlement and Security task lookup

The running `akd` process identified by the prior `com.apple.adid` peer logs returns a `CFString` for `adi-client` through the installed Security framework. The string equals the value in that process's live kernel-exported entitlements. The running `fairplayd` has the FairPlayIOKit access entitlement, while its live XML and DER exports omit `adi-client`. This distinguishes the ordinary kernel user-client admission credential from the credential checked when `adid` processes an XPC peer's request. [Native peer records](fairplay_native_xpc_observation_report.md) [FairPlayIOKit client entitlement provenance](live_fairplay_client_entitlements_report.md)

The installed kernel compares the token's PID and PID version before dispatching the selected code-signing operation. Controlled same-image and different-image execs preserved the PID and caused the pre-exec token to return `ESRCH`, while a refreshed token succeeded. [Live audit-token generation](live_audit_token_generation_report.md)

## Native process observations

It checked process start and executable fields, CDHash, fat-slice offset and validation category around each read. Each exported DER blob was byte-identical to the DER slot bound by the measured `arm64e` CodeDirectory. The verifier checked the top-level DER entries and matched their complete key set to the XML export. For `adi-client` it compared the DER UTF8String payload to the XML string and compared the actual Security framework return with that same string when a task-name right was available. ## Task-name, audit token and entitlement interfaces

The sample used the genuine audit token returned by the kernel for the `akd` task name and the verifier's own task name. Each successful call returned eight 32-bit words, with word 5 matching the queried PID. The verifier released the acquired task-name send reference after the token read. The Mach routines operate on a kernel task object and the verifier's MIG reply queue. Their installed emission sites and layouts were checked from libsystem_kernel UUID `780a6c1f-be02-34cc-84dd-00e05f61c89b`.

| Boundary | Data, rights and installed sites |
| --- | --- |
| `task_name_for_pid` | Takes the verifier's task port and the target PID. Trap `-44` at `0x180548bf8` returns a task-name send right in the verifier's namespace on the observed successes. |
| `task_info(TASK_AUDIT_TOKEN)` | MIG request `3405`, 40 B and header bits `0x1513`. The remote field uses `COPY_SEND` for the task-name right. The local field uses `MAKE_SEND_ONCE` for the reply queue obtained at `0x18054942c`. The emit call is `0x180549474` to `mach_msg2_internal`. |
| Token reply | MIG reply `3505` is expected at `0x1805494b4`. The user stub checks `40 B + 4 B * word_count` and copies the array at `0x1805495a4`. Flavor 15 with 8 words yields a 72 B message, excluding the trailer. XNU source supplies the token from the named task. |
| Security task construction | `SecTaskCreateWithAuditToken` at `0x1851e0fa4` copies the 32 B aggregate into object `+0x10` at `0x1851e0fdc`. |
| Entitlement load | The native macOS loader queries DER operation `16` with 8 B at `0x1851e1430`. It checks `ERANGE`, decodes the big-endian length and retries with that length at `0x1851e15c8`. The helper projects the PID and passes the stored token address as argument 5 at `0x1851e1268`. The authenticated import leads to `csops_audittoken`, BSD syscall 170, at `0x1805495b8`. |
| Dictionary lookup | The loader passes the span starting 8 B into the response to CoreEntitlements, then converts the context to a CF dictionary at `0x1851e167c`. `SecTaskCopyValueForEntitlement` uses the loaded dictionary at `+0x38`, calls `CFDictionaryGetValue` at `0x1851e1300`, and retains a present result at `0x1851e1310`. |

The Mach layouts are derived from installed instructions, and native verification observed the API statuses and returned token word counts. The `csops_audittoken` XNU source checks both token PID and PID version against the resolved process before the entitlement copyout. The native Security lookup uses this token-qualified route. The `fairplayd` and `adid` measurements use the separate PID-based `csops` route and describe their current exports. [XNU task MIG interface](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/mach/task.defs#L155-L168) [XNU token production](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/kern/task.c#L5420-L5434) [XNU token matching](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_proc.c#L3406-L3443) [Apple Security source](https://github.com/apple-oss-distributions/Security/blob/db15acbe6a7f257a859ad9a3bb86097bfe0679d9/sectask/SecTask.c#L116-L158) [DER load and lookup](https://github.com/apple-oss-distributions/Security/blob/db15acbe6a7f257a859ad9a3bb86097bfe0679d9/sectask/SecTask.c#L218-L349)

The installed `adid` slice matches the serving process's CodeDirectory and retains the authenticated call instructions at `0x100169100` and `0x1001691c8` identified by the prior receiver audit as the Security task creation and lookup sites. The return-pointer test at `0x1001691cc` precedes the computed branch at `0x1001691f0`. The kernel export is now evidence that the key is absent from the running `fairplayd`'s inputs to a native Security lookup. The actual value returned inside `adid` for a `fairplayd` peer, a native request or reply, and its linkage to a FairPlayIOKit transaction remain unknown. ## Assumption register

| Assumption and dependent result | Falsification probe |
| --- | --- |
| The matching PID and start fields identify the process seen in the earlier log window. The positive case associates the current `akd` entitlement with that process identity. | Compare the prior receipt and current inventories, and recheck the live process and slice identities after collection. A transaction-level token would be required to bind an earlier request. |
| The runtime exports can be compared with the selected signature and across encodings. | Recompute the CodeDirectory and special-slot hash, require DER byte equality and compare the XML and DER top-level key sets. Verify the DER type and exact string against the live Security result for PID 879. |
| The sample exercises the installed native Security framework and the token-qualified syscall. | Verify the running cache UUID, framework export entries, authenticated imports and both operation-16 call sites. Demand successful token and value lookups for `akd`, and no value or error for the verifier's self-control. |
| A task-name audit token is sufficient to exercise the Security lookup for a currently visible task. Its relationship to a transmitted peer token is conditional. | Check returned PID and exact width. A native receiver-side observation is required to confirm the selected peer token, result and branch in a specific XPC transaction. |

High impact for distinguishing the current FairPlayIOKit and ADID admission credentials and for identifying the live positive comparator. Medium impact for Mach attribution because the task-name and MIG rights belong to the verifier's metadata query. The query does not send application IPC to the daemons. The receipt omits token words, numeric Mach names and the entitlement string.
