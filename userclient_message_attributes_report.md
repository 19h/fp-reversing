# Schema payload consumption: FPMessageAttr and kernel random interfaces

The non-NULL schema-table payload feeds a 112-byte `site.FPMessageAttr` allocation and a complete source constructor. The constructor requests kernel `_random` 64 times. The caller always copies a cached 16-byte field and a header word; payload byte +4 selects whether it also copies a cached 32-byte field or retains the first generated field and sets an attribute flag. These are conditional source contracts. Native allocation, provider effects, payload type/lifetime, authenticated transfers and daemon/kext transaction identity remain unknown.

This advances the [lookup-result frontier](userclient_schema_lookup_result_report.md) from `0xfffffe000a636958` to the pending transfer at `0xfffffe000a636d30`, targeting `0xfffffe000a6575b0`. The target is not executed in this increment. The allocator-NULL alternative reaches a separate raw error publication and pending cleanup. Existing reference files suffice; no IDB or original input was modified.

## Control and architectural interfaces

F is the retained caller SP/frame base; C/S/H/J/Z retain their meanings from the lookup-result report. P is the raw nonzero selected-entry payload. A is the separate allocator result. Both remain symbolic. Non-NULL profiles assume readable P[0..55], writable A[0..111], nonwrapping extents and separation from each other, private roots, table header/array and image. NULL allocation requires no payload dereferenceability.

```text
actual schema scalar -> token541 lookup -> occupied-match raw payload P
    |
    +-> a636958: prepare callback and output cell
          |
          +-> a652e34: request typed attribute allocation
                |
                +-> A == 0 -> callback -> S+ab8 error -> pending a6621e4
                |
                +-> A != 0 -> 32 random bytes -> 32 random bytes -> defaults
                                  |
                                  +-> callback -> copy cached16 and read P+4
                                        |
                                        +-> mode0: copy cached32
                                        +-> mode!=0: set flag, retain generated32
                                              |
                                              +-> copy header -> pending a6575b0
```

## Kernel random provider cuts

| Original cut / emission PC | Source contract |
| --- | --- |
| `0xfffffe000bf09e48..0xfffffe000bf09e68`; BLRAA at `0xfffffe000bf09e64` | X0=load64(`0xfffffe000cb88f48`); target=load64(`0xfffffe0007e6c9a0`); IA modifier has upper16=0x4d5f and lower48=provider-slot address |
| `0xfffffe000bf09e68..0xfffffe000bf09e8c`; BLRAA at `0xfffffe000bf09e88` | X0=load64(the same state-global address); W1=zero-extended load16(TPIDR_EL1+0x1b8); W2=4 bytes; X3=local SP+0xc; target=load64(`0xfffffe0007e6c9a8`); IA modifier upper16=0xedeb, lower48=second-slot address |
| `0xfffffe000bf09e8c..0xfffffe000bf09e94` | W0=load32(local SP+0xc) AND 0x7fffffff |

The 16-bit TPIDR-relative field is named by its offset because its native semantic identity is not established here. Provider slots/state and TPIDR are symbolic interface inputs to separate cuts; state-pointer equality across the intervening provider call is not established. Provider identity, locking, readiness, entropy and native effects remain unknown; the first call's return is not claimed to be a data output.

For every incoming u32 r, the kext normalizes r=0xffffffff to zero and stores the low byte of `r - ((r << 1) AND 0xffffff8f) - 0x39`, with u32 modular arithmetic. The equivalent byte formula is `r==0xffffffff ? 0xc7 : low8(r) XOR 0xc7`. The kernel's 31-bit mask excludes the special value, so the composed byte equals `low8(provider_word) XOR 0xc7`. No independence, uniformity or entropy bound follows. All 64 requests occur even in mode0, where the caller subsequently overwrites the first 32 generated bytes.
