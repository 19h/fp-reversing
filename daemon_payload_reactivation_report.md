# Constructor-payload reactivation, field reset and representation cycle

Four conditional daemon continuations now pass the previously undefined table read, recover the constructor's 2184 B payload, generate a four-byte scalar, update a header, clear 30 slot fields, reseal the payload and reach a pending `malloc(74)`. The payload is exactly 24 B of header followed by 30 slots of 72 B. Original source publishes its pointer at J+`0x100` in raw form after inversion and in encoded form after resealing. Native structure names, ownership, producer/caller epoch coherence and daemon-kext transaction pairing remain unknown. [RA1-RA6; RA-A1-RA-A10]

The complete four-byte generator call also establishes separate roles for completion status and adapter adjustment. Its request receives a status word, while a different temporary cell is initialized and restored around the call. Their nonaliasing does not itself establish a caller inconsistency. This corrects the earlier mismatch interpretation in the [generated-stream](daemon_generated_stream_report.md) and [auxiliary-state](daemon_auxiliary_state_report.md) reports; their retained bytes, source equations and conditional native-epoch limitations remain unchanged. [RA2-RA4; RA-A6]

## Producer identity and the explicit epoch boundary

Use D=`0x6500115274`, J=`0x6500115b20`, N=2184=`0x888` B and seed32=`0x4546796b`. D is the exact carried address, including its low three bits equal to four. It is not rounded to an eight-byte boundary. D+N=`0x6500115afc`, 36 B before J. The constructor's source codec at `0x100462818..0x100462974` uses the same payload address, extent and seed as the current inverse. [RA1-RA4; RA-A1-RA-A3]

The producer computes `seed=u32(low32(D)*0x41da4f94) XOR 0x487b0e7b`, using its source-text fold at `0x100462810..0x100462818`. The parent decoder's eight source-text lookups recover the same fold and leave W9=`0x4546796b` at the pending inverse. This is matching address-bound representation evidence, without a native epoch join. [RA1-RA2,RA5]

The original 160048-visit constructor trace contains nine overlapping writes to J+`0x100`. Eight are earlier fill-byte writes; the last, source `0x1002fb264` at visit index145895, writes `2e4c2bee000003c5`. As a little-endian u64 this is `0xc5030000ee2b4c2e`; the parent decoder reconstructs D. Source `0x1002fb26c` at visit145897 separately zeros J+`0x1e0`. No later constructor write overlaps the encoded D span after the codec completes. [RA1-RA5]

All 2184 payload bytes in the retained context snapshot have source-known mask bits. They equal the constructor's encoded payload byte for byte. All 13 retained raw-context seal profiles preserve the same eight J+`0x100` bytes. The current extractor transfers only these 2184 encoded bytes at the parent's undefined read. It adds no owner, pointer field, register, cache word, allocation result or native API effect. The existing heap owner contains D; mapped backing bytes outside source definitions remain undefined. Equality of source bytes and addresses does not establish that the separate producer and caller states belong to one native execution. [RA2-RA5; RA-A2-RA-A3]

## Exact inverse, raw publication and four-byte request

Let all u32/u8 operations reduce modulo 2^32/2^8 respectively. For byte index i define `m(i)=low8(seed XOR u32((i+seed)*(i-seed)))`. The constructor first computes `encoded_byte=u8((raw_byte XOR m(i))*0x93)`, then permutes the 273 little-endian u64 words with descending i=272..1, `j=u32((u32(seed+i) XOR seed)*0x01000193) mod i`, swapping words i and j. The current inverse executes ascending i=1..272, then computes `raw_byte=u8(encoded_byte*0x9b) XOR m(i)`. The product `0x93*0x9b` is 1 modulo256. These are recovered representation transforms; a cryptographic role is unknown. [RA1-RA4; RA-A4]

## Header, slots and resealed pointer

Original arithmetic `0x1004dec48..0x1004decac` transforms W28 into `header=(BE32>>1)+1`, with phase W15=`0x6cf4`; source `0x1004decb8` writes this u32 at D+`0x10`. The equation holds for every BE32 under that phase. Its unsigned range is1..`0x80000000`; the low generated bit is discarded. Source `0x100570e28` clears the u32 at each D+24+72*j. The last clear is at offset`0x840`; the last complete slot ends at D+2184. These fields were already zero in the transferred constructor baseline; the original stores still execute. Every other raw payload byte remains equal to that baseline. [RA1-RA4; RA-A5-RA-A7]
